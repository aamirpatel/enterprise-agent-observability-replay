# Suggested Acceptance Criteria

A strong submission demonstrates:

1. A trace is captured from user request through final answer.
2. Tool calls, outputs, status, timing, and errors are visible in order.
3. Sessions can be searched by date, status, trace ID, session ID, tool, and failure category.
4. A selected session can be safely replayed with synthetic or recorded mock inputs.
5. Original and replay outcomes can be compared.
6. Failures are classified and linked to supporting trace evidence.
7. Dashboards show health, success and failure rates, latency, trends, and top failed APIs.
8. Sensitive fields are masked and replay actions are audited.
9. The solution runs through Docker Compose and includes tests and operating instructions.
